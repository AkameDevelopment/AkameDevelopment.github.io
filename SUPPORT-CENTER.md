# Support Center

Uses the existing `public.community_requests` table. No parallel ticket store.

## Changed files
- `support.html`, `support-center.js`, `support-core.js`, `support-center.css`: authenticated member workspace, bug/feature forms, paginated personal ticket list, deep links and conversation details.
- `admin.html`, `admin-requests.js`: existing admin section extended with server filters, number/title search, ticket details, status and public replies. Owner/admin permission remains unchanged.
- `mobile-nav.js`: Support account entry with life-buoy icon; removed duplicate Dashboard account entry; safe return to Support through the existing index OAuth callback.
- `akamesmp-notifications.js`: real support event loading, filtering, unread state and ticket links.
- `community.html`, `community-rework.js`: old support forms and outdated notices removed; old support hashes redirect.
- Other root HTML files: only shared navigation cache version changed.
- `supabase/migrations/20261114182044_extend_existing_support_center.sql`: applied to the connected production project.

## Database
Ticket UUIDs and existing data remain. `ticket_seq` is generated by an atomic PostgreSQL sequence in an INSERT trigger; `ticket_number` is a stored generated, unique AK reference. Neither can be supplied or changed by frontend roles. Sequence gaps are expected after failed or rolled-back transactions, including QA; numbers are unique, not gapless. Values above six digits are never truncated.

`image_url`, `benefit` and append-only `replies` extend the existing tickets. Previous member-visible `admin_note` values are backfilled into replies; no private internal notes are published. The old interface already displayed admin_note to its author. `reviewing` now displays In Progress; legacy `planned` is retained. `declined` displays Rejected.

RLS requires an authenticated Discord identity (verified from auth.identities, not editable metadata), ownership or the pre-existing owner/admin role. Column grants allow members to submit fields, and only authorized admins to update status and admin_note. Direct modification of number, author, timestamps or reply history is denied. Anonymous access and dangerous default TRUNCATE grants were removed. An unexposed, trigger-only private function creates recipient-scoped support_notifications events; this is an event table, not another ticket store. The existing notification center reads these events. Support notifications are independent of the Community preference.

## Verification
- 30 DOM/function tests: auth gates, both forms, escaping/HTTPS validation, own ticket details, reply display, English, sign-out cleanup, admin permission gate/search/replies, navigation/notification behavior at mobile and desktop sizes.
- Database role tests in rolled-back transactions: own versus foreign tickets, member update denial, admin replies/status, immutable references, notification ownership and non-Discord denial.
- Two database sessions each inserted 25 tickets in rolled-back transactions; all references were unique, enforced by a shared sequence and unique constraint.
- Security advisors checked before/after: no new support findings. Existing public-profile/stat RPC warnings and password-protection setting remain outside this change.
- Node syntax and HTML duplicate-ID checks.

## Manual acceptance
No extra OAuth redirect setup is needed: sign-in reuses the existing index.html callback and a fixed same-origin Support return marker. Complete one real Discord OAuth round trip in a browser; approve an actual ticket as owner/admin and check its notification. Visual Safari/Chrome, light/dark and touch checks remain manual: no managed browser is available in this workspace. Automated DOM bounds tests are not visual browser tests.
